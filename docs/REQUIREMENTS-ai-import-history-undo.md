# REQUIREMENTS — AI 임포트 처리 내역 & 개별 되돌리기

## 기능 요구사항 (FR)

| ID | 요구사항 | 단계 | 수용 기준(AC) |
|---|---|---|---|
| FR-1 | AI 저장 시 각 건을 감사 로그에 기록 | P1 | 저장 후 event_logs에 건별 `payment.import_add` 존재, meta에 batchId·source·이름·강좌·금액 |
| FR-2 | 한 번의 임포트를 batchId로 묶음 | P1 | 같은 임포트의 모든 건이 동일 batchId |
| FR-3 | 결과 카드에 저장된 건 개별 표시 | P2 | 이름·강좌·금액·종류(저장/새등록/환불) 목록이 보임 |
| FR-4 | 개별 되돌리기 | P3 | [되돌리기]→확인→해당 payment_record 삭제, enrollment 잔액/상태 재동기화 |
| FR-5 | 신규 등록 정리 | P3 | 되돌릴 건이 신규 등록이면 확인 후 등록도 삭제(단, 그 등록에 다른 결제 없을 때만) |
| FR-6 | 배치 전체 되돌리기 | P4 | [전체 되돌리기]→확인→batch의 모든 건 취소, 성공/실패 집계 표시 |
| FR-7 | 되돌리기도 로그 기록 | P3 | `payment.import_undo` 이벤트 존재 |
| FR-8 | 부분 실패 정확 보고 | P3/P4 | "N건 취소, M건 실패"로 표시(성공한 것만 취소됨 처리) |
| FR-9 | 나중에 되돌리기 | P5 | 임포트 후 채팅을 닫아도 이벤트 로그에서 그 임포트를 찾아 되돌릴 수 있음 |
| FR-10 | 정합성 가드 | P3 | 임포트 후 수정됨→경고 후 진행 · 환불 걸림/합계 음수→차단 · 이미 삭제→무동작 · 신규등록에 다른 결제 있으면 등록 보존 (§PLAN 3.6) |
| FR-11 | 서버 재검증 | P3 | undoImport가 클라이언트 판정을 신뢰하지 않고 실행 직전 현재 상태로 planUndo 재검사 |

## 비기능 요구사항 (NFR)
- **NFR-1 조직 격리**: 되돌리기는 현재 조직(RLS) 기록만 대상.
- **NFR-2 비가역 작업 확인**: 모든 삭제 전 사용자 확인 모달.
- **NFR-3 결정론/순수 분리**: 로그 생성·되돌리기 계획은 순수 함수로 단위테스트.
- **NFR-4 양 앱 일관성**: ai-chat UI는 tutomate/tutomate-q 동일 파일 유지(복사).
- **NFR-5 타입 게이트**: 양 앱 tsc exit 0.
- **NFR-6 실기기 검증**: 돈 삭제 경로는 실기기 테스트 완료를 릴리스 조건으로.

## 범위 밖 (Out of scope)
- 스키마(테이블/컬럼) 변경 — event_logs.meta로 처리.
- 되돌린 것의 "다시 실행(redo)".
- 임포트 외 일반 수동 납부의 배치 되돌리기.
